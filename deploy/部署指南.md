> 面向零基础。照着做，每一步都有验证方法。

## 先搞清楚原理（30 秒）

你的看板就是**一个网页文件**（`index.html`，只有 54KB）。

部署 = **把这个文件放到一台人人能访问的机器上**。

就这么简单。不需要数据库、不需要后端、不需要装 Python。

**而且这个文件很聪明**：别人打开它的时候，它会自己去 DefiLlama 和 CoinGecko 抓最新的收入、回购、价格数据。
所以你**只需要部署一次**，之后不用天天重新上传。

# 方案 A：你已经有服务器（推荐）

## 第 1 步：上传文件

在你自己的电脑（Mac）上打开「终端」，执行：

```bash
cd /Users/alasijiadegou/Documents/Codex/2026-09-28/https-x-com-ponsdotfamily-https-x

scp -r deploy root@你的服务器IP:/root/
```

- 把 `你的服务器IP` 换成你服务器的公网 IP，比如 `47.100.23.45`
- 回车后会让你输服务器密码（输入时屏幕上不会显示，是正常的，输完直接回车）
- 看到进度条走完 = 上传成功

> **找不到服务器 IP？** 登录阿里云/腾讯云控制台，在「云服务器 ECS / 轻量应用服务器」列表里能看到「公网 IP」。

## 第 2 步：登录服务器并运行一键脚本

```bash
ssh root@你的服务器IP
```

连上之后（命令行前缀会从你 Mac 的名字变成服务器名字），执行：

```bash
cd /root/deploy
bash deploy.sh
```

脚本会自动做完这些事：
1. 装 nginx（如果没有的话）
2. 把看板放到 `/var/www/pons-dashboard/`
3. 写好配置、放行防火墙、启动服务
4. **最后直接打印出访问网址**

## 第 3 步：打开验证

终端最后会打印类似这样一行：

```
别人打开这个网址就能看：
http://47.100.23.45
```

把这个网址发给任何人，他们用手机、电脑浏览器都能打开。

# 方案 B：你还没有服务器

## B-1 免费方案（不用花钱，30 秒搞定）

打开这个网址：

**https://app.netlify.com/drop**

然后把 `deploy` 文件夹**直接拖进网页里**（注意是整个文件夹，不是单独的 index.html）。

等 10 秒左右，它会给你一个网址，形如 `https://xxxx-xxxx.netlify.app` —— 这就是你的看板公网地址。

> ⚠️ **重要提醒**：Netlify 和 Vercel 的免费域名在国内**经常打不开或者很慢**。
> 如果你和你的朋友主要在中国大陆，**请用方案 A（自己的服务器）**，国内服务器用 IP 直接访问最稳。

## B-2 Cloudflare Pages（免费，国内相对能开）

1. 打开 https://dash.cloudflare.com/ 注册一个账号（免费）
2. 左侧菜单 → `Workers & Pages` → `Create` → 选 `Pages` → `Upload assets`
3. 项目名随便起，比如 `pons-dashboard`
4. 把 `deploy` 文件夹拖进去 → 点 `Deploy`
5. 得到 `https://pons-dashboard.pages.dev` 这样的网址

## B-3 买一台服务器（约 60~100 元/年）

- 阿里云 / 腾讯云 → 搜「轻量应用服务器」
- 配置选最低档就够（1核1G，你的看板只有 54KB）
- 系统镜像选 **Ubuntu 22.04** 或者 **Debian 12**
- 买完拿到公网 IP，然后回到**方案 A** 执行

> 💡 **国内服务器要注意**：用 IP 访问不用备案；但如果你想绑自己的域名（比如 `panel.你的名字.com`），**必须备案**，流程要 1~3 周。
> 只是发给朋友看的话，用 IP 就够了，**不用备案**。

# 打不开？按这张表排查

| 现象 | 原因 | 怎么解决 |
|---|---|---|
| **浏览器一直转圈/超时** | 云服务商安全组没放行端口 | 登录云控制台 → 找到这台服务器 → 安全组/防火墙 → **放行 TCP 80（和 8080）**（这是最常见的坑，90% 是这个问题） |
| 显示「无法访问此网站」 | nginx 没起来 | 服务器上执行 `systemctl status nginx` 看状态 |
| 显示 nginx 默认欢迎页 | 配置文件没生效 | 执行 `nginx -t` 检查，再 `systemctl reload nginx` |
| 本机能开、外网不能开 | 服务器自带防火墙 | 执行 `ufw allow 80` 或 `firewall-cmd --add-port=80/tcp --permanent && firewall-cmd --reload` |
| 打开是空白 | 浏览器缓存 | 强制刷新：Mac 按 `Cmd+Shift+R`，Windows 按 `Ctrl+F5` |
| 只能自己打开，别人打不开 | 你连的是内网 IP（`192.168.x.x` / `10.x.x.x`） | 必须用**公网 IP**（在百度搜「我的IP」能看到你自己电脑的公网IP；服务器的公网IP在云控制台看） |

**终极排查**：在服务器上执行 `curl http://127.0.0.1/` 
- 有 HTML 输出 → 服务器没问题，是**安全组/防火墙**的问题
- 报错 → 是 nginx 的问题，执行 `nginx -t` 和 `tail -50 /var/log/nginx/pons-dashboard.error.log`

# 以后怎么更新看板？

好消息：**基本不用更新**。看板打开时会自动联网抓最新数据。

但如果你改了看板本身（比如加新指标），更新只要一条命令。在 Mac 上执行：

```bash
cd /Users/alasijiadegou/Documents/Codex/2026-09-28/https-x-com-ponsdotfamily-https-x
bash deploy/push.sh 你的服务器IP
```

脚本会自动把最新的看板传上去。

# 换个端口 / 绑域名（进阶，可选）

**换端口**：编辑 `deploy.sh` 第 10 行 `PORT=80`，改成别的数字，重新跑一次脚本。
默认用 80，网址就是干净的 `http://你的IP`（不用带端口号），也最不容易被防火墙拦。

**绑域名**（需要域名 + 备案）：
1. 域名商后台加一条 A 记录，指向你的服务器 IP
2. 编辑服务器上 `/etc/nginx/conf.d/pons-dashboard.conf`，加一行 `server_name panel.你的域名.com;`
3. 执行 `systemctl reload nginx`

# 用 Docker 部署（如果你熟悉 Docker）

```bash
cd /root/deploy
docker compose up -d
```

访问 `http://你的服务器IP:8080`（Docker 版映射到的是 8080）。

停止：`docker compose down`

# 文件清单

```
deploy/
├── index.html          ← 看板本体（唯一必须的文件）
├── deploy.sh          ← 服务器上跑这个，全自动部署
├── push.sh      ← 本地跑这个，一键更新服务器上的看板
├── nginx.conf          ← nginx 配置（脚本会自动用，也可手动复制）
├── docker-compose.yml  ← Docker 部署用
├── Dockerfile          ← Docker 部署用
└── 部署指南.md          ← 就是本文档
```

**最省事的做法**：只记住 `deploy.sh` 这一个文件就够了。
