## 生成流程

```
work/template.base.html     ← 干净母版（不含名片、不含主题）
        │
        ├─ rebuild_template.py   注入：作者名片 + 主题系统（深/浅色令牌）
        ▼
work/template.html          ← 真正的模板（改样式改这里的上游）
        │
        ├─ build_monitor.py      联网抓 DefiLlama/CoinGecko → work/dashboard-data.json
        │  （或 render_only.py   不联网，用现有 json 直接渲染）
        │     ├─ leaderboard.py  顺带抓「全站收入榜」，裁成 ~7KB 的 leaderboard 字段
        │     └─ buyback.py      顺带抓「链上销毁量 + 全站回购榜 + 同行市值/成交额」→ burn 字段（v2.9）
        ▼
outputs/pons-stonkfun-monitor.html
        │
        └─ deploy/push.sh        推到服务器 /var/www/pons-dashboard/index.html
```

**改东西的顺序**：改 `template.base.html` 或 `rebuild_template.py` → 跑 `rebuild_template.py` → 跑
`render_only.py`（或联网的 `build_monitor.py`）→ `bash deploy/push.sh`。

⚠️ `rebuild_template.py` 是 v1.5 之前的生成器，**现在不要再跑**：它只会从 `template.base.html`
重新生成，会把 v1.3 之后加的板块（收入排行 / 回购销毁 / BGM / 歌词 / 共勉 / 浏览计数…）全部抹掉。
从 v1.3 起 `work/template.html` 就是唯一母版，**直接改它**（改前先 `cp work/template.html work/template.html.bak-xxx`）。
真要从 base 重建：`PONSFI_ALLOW_REBUILD=yes python3 work/rebuild_template.py`（脚本已加保险，默认拒绝执行）。

## 主题系统（自动适配深色 / 浅色）

- 令牌定义在 `rebuild_template.py` 的 `DARK` / `LIGHT` 两段，浅色写了两遍（手动切换 + 跟随系统）
- 右上角按钮三态循环：`◐ 系统` → `☀ 浅色` → `☾ 深色`，存在 localStorage 的 `pons-theme`
- 默认「跟随系统」：系统深色就深色，系统浅色就浅色
- 想让它**永远深色**：点按钮切到「深色」；或把 `rebuild_template.py` 里默认值 `||"auto"` 改成 `||"dark"`
- 所有颜色走 CSS 变量，图表颜色也用 `var(--pons)` / `var(--stonk)`，切主题不用重绘
- SVG 里颜色一律用 `style="stroke:var(--x)"`，**不能**用 `stroke="var(--x)"`（演示属性不支持 var()）

## 收入排行板块（v1.3 新增）

看板里「收入排行 · 在整个行业里的位置」这一块，数据来自 DefiLlama 全站收入榜
（`https://api.llama.fi/overview/fees?dataType=dailyRevenue`，约 2,455 个协议、原始 4.2MB）。

- **裁剪**：`work/leaderboard.py` 把 4.2MB 裁成 ~7KB，只留
  - 每个口径（24h / 7日 / 30日）的榜首 Top10
  - 两个目标协议的名次 + 上下各 4 名（已经在 Top10 里时改成「身后 8 名」）
- **快照**：结果写进 `work/dashboard-data.json` 的 `leaderboard` 字段，跟着面板一起发布
  - 只想更新排行、不重新抓收入：`python3 work/leaderboard.py` 再跑 `render_only.py`
  - ⚠️ Pons 的主协议 slug 是 **`pons-v2`**（`pons-v1` 已停用，24h 只剩几千美元）
- **页面刷新**：浏览器打开时若本地缓存超过 6 小时，会自己拉一次全站榜（gzip 后约 860KB，
  缓存在 localStorage 的 `pons-rank`）；也可以点板块里的「↻ 更新排行」强制拉
- **前端裁剪逻辑**：`template.base.html` 里的 `buildRankBoard()` 与 `leaderboard.py` 的
  `build_board()` 是同一套规则，改了一个要同步改另一个，否则快照和刷新结果会不一致

## 名次卡怎么读

| 元素 | 含义 |
|---|---|
| 大号 `#22` | 当前所选口径下的全站名次 |
| `前 1%` | 百分位（名次 ÷ 协议总数） |
| 对数刻度轴 | 左边是 #1（收入最高），右边是 #总数；标记越靠左越好，刻度是指数级的 |
| 三口径小卡 | 24 小时 / 7 日 / 30 日 各自的名次与收入额 |
| 环比那一行 | 30 日口径名次 → 现在名次（升 / 降多少位） |
| 紫色提示条 | 再涨多少「每日收入」就能超过上一名（同口径对比） |

## 浏览量统计（v1.4 新增）

页脚最下面一行「👁 总浏览 / 今日 / 今日访客」是**自己服务器上的计数器**，不接第三方统计。

```
访客浏览器 ── /api/hits ──▶ nginx 反代 ──▶ 127.0.0.1:8788 (pons-counter 服务)
                                              └─▶ /var/lib/pons-counter/counts.json
```

- 服务代码：`deploy/counter/counter.py`（纯 Python 标准库）+ `deploy/counter/pons-counter.service`（systemd）
- 服务器路径：`/opt/pons-counter/counter.py`，数据在 `/var/lib/pons-counter/counts.json`
- nginx：`/etc/nginx/conf.d/pons-dashboard.conf` 里的 `location = /api/hits`（备份 `.bak-pv`）
- 计数规则：每次打开页面 +1 次浏览；**同一天同一 IP 只算 1 个访客**；存的是加盐哈希，不存原始 IP；
  爬虫 / 探针（bot、spider、curl、wget、监控 UA）不计入；每天保留最近 400 天
- 本地 `file://` 打开**不计数**（只在 http/https 下才请求接口）
- 计数服务挂了页面不会报错，只是页脚不显示这一块

常用命令（在服务器上）：

```bash
systemctl status pons-counter          # 看服务状态
curl https://ponsfi.xyz/api/stats      # 只读看数字（不计数）
sudo systemctl restart pons-counter    # 重启
sudo rm /var/lib/pons-counter/counts.json && sudo systemctl restart pons-counter   # 清零重来
sudo journalctl -u pons-counter -n 30  # 看日志
```

改动计数服务后重新安装：把 `deploy/counter/` 三个文件传上去，`sudo bash install.sh`。

## 行情 BGM（v1.5 起多曲轮换 · v2.1 跌档三首 · v2.4 涨档两首）

- 涨档：`audio/up.mp3`《逍遥仙》→ `audio/up-bufan.mp3`《不凡》→ 来回轮换
- 跌档：`audio/down-meng.mp3`《梦的翅膀受了伤》→ `audio/down.mp3`《兄弟抱一下》→ 来回轮换
  （进跌档先放第一首；一首放完自动切下一首，靠 `ended` 事件驱动）
- 曲目表写在 `rebuild_template.py` 的 `BGM_TRACKS` 里，想加歌就往对应档位的数组里加一项：
  `{ src:'audio/xxx.mp3', name:'i18n 里的曲名 key' }`，并在 `template.base.html` 的 i18n 里补这个 key
- 轮换游标 `bgmRot`：每档记住"下一首该放第几首"；切档（涨↔跌）不会打断同档正在放的那首
- 只有一首的档位 `loop=true`（单曲循环）；两首及以上的档位 `loop=false`（放完换下一首）
- mp3 放服务器 `/var/www/pons-dashboard/audio/`，本机留一份在 `deploy/audio/`（zip 备份里不含 mp3）
- 文件缺失/加载失败 → 自动回落到内置原创占位旋律（Web Audio 合成），不会静音报错
- 播放器详情面板会显示「第 1/2 首」和当前曲名，方便确认在放哪首

换歌步骤：把 mp3 传到 `/var/www/pons-dashboard/audio/`（名字对上曲目表）→ 不需要改代码；
要改曲名或曲目顺序，才需要改 `BGM_TRACKS` + i18n 后重新 build & 部署。

## 横幅歌词（v1.6 新增 · v1.7 校对与收起）

作者名片中间那块空白，现在会跟着 BGM 显示「正在播放」的歌词：当前行居中高亮、上下行渐隐，
下面一条细进度条跟着播放进度走；窄屏（≤900px）自动铺满一整行。

- **歌词文件**：跟音频同目录同名，放服务器 `/var/www/pons-dashboard/audio/`，本机留一份在 `deploy/audio/`
  - `up.lrc`（逍遥仙）· `up-bufan.lrc`（不凡）· `down-meng.lrc`（梦的翅膀受了伤）· `down.lrc`（兄弟抱一下）· `down-wuren.lrc`（无人之岛）
  - 格式：标准 LRC `[mm:ss.xx]歌词`；`作词/作曲/编曲` 等元数据行会被自动过滤
  - mp3 和 lrc 的**文件名必须成对**（`up.mp3` ↔ `up.lrc`）
- **加新歌**：mp3 + lrc 一起传到 `audio/` → 在 `BGM_TRACKS` 里那一项补 `lrc:'audio/xxx.lrc'` → 重新 build & 部署
- **引擎位置**：`rebuild_template.py` 的 `BGM_JS` 里，`lyricParse / lyricNote / lyricMount / lyricSeek / lyricOnTrack / lyricRelang`
  - 取词时机：**真正出声之后**才 fetch（`go()` 里调 `lyricOnTrack`），自动播放被浏览器拦下时不加载
  - 歌词是异步来的，到位时可能已经唱到中段 → `lyricMount` 会按 `audio.currentTime` 直接归位，不从第一行滚过去
  - 切换/停播会作废在途请求（`lyTok` 令牌 + `bgmCur===band` 双重校验），不会出现「没在放歌却显示歌词」
  - 找不到 lrc / 解析为空 / mp3 缺失走占位旋律 → 单行提示「纯音乐 · 暂无歌词」
- **音源短于歌词时间轴会自动降级**：例如《梦的翅膀受了伤》现在只有 19.38 秒试听片段，而歌词时间轴到 3:57，
  硬套会出现「永远是第一句、进度条不动」→ 引擎改成显示「♪ 试听片段 · 歌词暂不同步」。
  **换成完整版 mp3（同名覆盖 `audio/down-meng.mp3`）后歌词自动恢复同步，不用改代码。**
- 状态文案在 `template.base.html` 的 i18n 里（中英都要写）：`lyIdle / lyLoading / lyNoLyric / lyClip`
- 样式在 `rebuild_template.py` 的 `CSS_BODY` 末尾（`.lyric / .ly-in / .ly-window / .ly-track / .ly-line / .ly-bar`），
  行高固定 18px、窗口 54px（3 行），JS 里的 `LY_LH` 要跟 CSS 对齐
- 切语言时 `setLang()` 会调 `lyricRelang()`：有歌词不动，只有提示文案跟着换语言
- ⚠️ `.lrc` 走的是 nginx 的 `/audio/` 缓存（7 天）+ Cloudflare：**改了歌词内容但文件名没变时，可能被缓存挡住**。
  换歌词内容时建议改个文件名（如 `down-v2.lrc`）并在 `BGM_TRACKS` 里同步，或在腾讯云/Cloudflare 清一次缓存。

### v1.7 的三处修正（改歌词/改交互必看）

1. **歌词版本必须跟 mp3 是同一版录音**
   - 线上原用的 `deploy/audio/down.lrc` 来自网易云「兄弟抱一下 **2021 版**」，而本站 mp3 是
     **庞龙《美好》专辑版**（`afinfo` / ID3 里 `TALB=美好`）—— 两版编曲完全不同：2021 版 2:40 就唱完了，
     还多一段原版没有的段落，所以看着「怎么都对不上」。
   - 现在曲目表里改用 `audio/down-v2.lrc`（与专辑版逐句对齐）。
   - **校对方法（不靠耳朵）**：`afconvert -f WAVE -d LEI16@22050 -c 1 x.mp3 /tmp/x.wav` 转成 wav，
     再用 python 逐 0.1~0.5 秒算 RMS 画能量包络 → 副歌处必然最响、主歌处必然掉下去，
     拿歌词里的「副歌/主歌」时间点去对，一眼就能看出偏没偏。
   - 仍有个别句对不齐时，在 `BGM_TRACKS` 那一项加 `lrcOffset: 1.2`（秒）：**正数＝歌词提前，负数＝延后**。
2. **没有歌词可显示时整块收起**（`.lyric.hidden{display:none}`）
   - 待命 / 加载中 / 纯音乐 / 试听片段 → 全部走 `lyricClear()`：清空 + 淡出 + 从排版里收掉，
     作者名片自动变回紧凑布局（手机上省一行高度），不再出现「点右下角播放」这类空话。
   - `lyricShow()` 只在真的挂上歌词（`lyricMount`）时调用。
3. **BGM 详情面板：点别处 / 滑动 / 滚轮自动收起**
   - 监听 `pointerdown / mousedown / touchstart / touchmove / wheel / scroll`，
     目标在 `#bgm` 里就放过（点面板自己不算），否则 `bgmDetHide()`。
   - ⚠️ 坑：`scroll`/`wheel` 的事件目标是 **window（不是 Node）**，直接 `r.contains(ev.target)`
     会抛 TypeError、监听器静默中断 → 必须写成 `ev.target.nodeType && r.contains(ev.target)`。

### v1.9 新增：共勉栏（六句话轮播 + 点赞）· 2026-10-03

> ⚠️ v2.0 起这块已经搬进作者名片、去掉轮播（见文末「v2.0」一节）；点赞服务端的部分没变。

指标说明下面、页脚上面多了一块「共勉」：

- **六句话每 8 秒换一句**：只淡换文字，卡片 / 点赞按钮都不动；鼠标停在卡片上暂停，切到别的标签页也暂停。
- **点赞按钮固定在右侧**：不随句子变化消失。**只加不减、可以连点**。
  - 点下去：心形短暂变实心 + 数字蹦一下 + 冒一个「+1」+ 一把撒花粒子（canvas 手绘，零依赖、无第三方库）
  - 连点先在本地累加（`QPend`），攒成一批再发：5 连点 = `d=1` + `d=4` 两个请求，不是 5 个
  - 撒花在 `prefers-reduced-motion:reduce` 下自动跳过
- **六个句子共用同一个累计数**（不是每句一个数，也不是本地假数）
  - 前端：`rebuild_template.py` 的 `QUOTE_JS`（`qPaint / qLike / qFlush / qConfetti`）
  - 后端：`deploy/counter/counter.py` 里的 `/likes`（只读）与 `/likes?d=N`（+N，**只认正数**，单次 ≤ 20）
  - nginx：`/etc/nginx/conf.d/pons-dashboard.conf` 的 `location = /api/likes` → `127.0.0.1:8788/likes`
  - 数据：`/var/lib/pons-counter/counts.json` 里的 `likes` / `likeDays`
- 改文案：`template.base.html` 的 i18n `secQuote / quotes[] / qLike / qLikes / qThanks / qLikeTip / qRotTip`，**中英各一份**。

**想手动改赞数**（接口只加不减，所以只能直接改数据文件）：
```bash
sudo systemctl stop pons-counter
sudo python3 -c "import json;p='/var/lib/pons-counter/counts.json';d=json.load(open(p));d['likes']=100;d['likeDays']={'2026-10-03':100};json.dump(d,open(p,'w'))"
sudo chown www-data:www-data /var/lib/pons-counter/counts.json
sudo systemctl start pons-counter
```

**注意**：`likeDays` 是按北京时间的每天新增；`likes` 才是总数（页面上显示的是它）。

### v2.0 改动：共勉搬进作者名片 + 默认口径改成 24h / 日收入 · 2026-10-03

作者名片中间原来空着一块，v2.0 把「共勉」整块搬了进去，并和歌词共用同一个位置。

**结构**（`rebuild_template.py` 的 `AUTHOR_HTML`）：
```
.author
 ├─ .author-me        头像 + 名字 + @handle（点进 X）
 ├─ .qbox#qbox        共勉：一句 + 心形点赞胶囊      ← v2.0 新增位置
 ├─ .lyric#lyric      歌词（放歌时出现）
 └─ .author-acts      关注按钮 + 打赏按钮
```
样式在 `QUOTE_CSS`（`.qbox / .qtext / .q-like`），逻辑在 `QUOTE_JS`，两边都在 `rebuild_template.py`。

**1. 每次刷新只显示一句、不轮播**
- `qPick()` 从 i18n 的 `quotes[]` 里随机挑一条；`localStorage['pons-q-last']` 记着上一条，下次刷新不会重复。

**v2.0.1 补丁（2026-10-03，只上线了十几分钟就修掉的问题）**

症状：作者名片里共勉只占一半宽度、右边留一大片空白，长句被挤成两行；歌词块明明没显示却一直占着位置。

根因（**踩过的坑，别再踩**）：`QUOTE_JS` 里的状态量原来用 `let` 声明（`QBoxT / QRetryT / QN / QPend…`）。
- **函数声明会提升，`let` 不会** —— `qBoxShowSoon()` 在 `BGM_JS` 结尾的初始化（`lyricPaintIdle()`）时就被回调到了，而那时 `let QBoxT` 还在"暂时性死区"（TDZ），抛 `Cannot access 'QBoxT' before initialization`；
- 这个异常被初始化外面那层 `try{ lyricPaintIdle(); }catch(e){}` **静默吞掉**，于是 `lyricHide()` 后半段（620ms 后加 `hidden` 收起歌词块）根本没执行 → 歌词块永久占位。

修法：把这几个量改成 `var`（初始化为 undefined，不进 TDZ）。教训：
1. **跨模块（BGM_JS ↔ QUOTE_JS）被回调的函数，内部引用的状态量一律用 `var`**，别用 `let`；
2. 初始化包 `try/catch` 时至少 `console.warn` 一下，不然这类错误完全无声。

同时顺手做的观感调整：共勉正文 12.5px → 13px（一行能塞下最长那句）；点赞胶囊常驻**粉色心形 + 淡粉底**、`margin-left:auto` 靠右贴齐，和右边的「关注 / 打赏」连成一组，不再吊在句子后面。

## v3.0「24 小时回购」（2026-10-04）

**为什么做**：用户提了三件事 —— ① 数据看着有点滞后 ② 30 天回购离我太远，我要看 24 小时
③ 回购榜和三方对照表都补上 24 小时口径（参考 ponsfamily.com/analytics、stonkfun.xyz/revenue、hyperleaf.finance/app/buybacks）。

**改了什么**

1. **回购强度榜加「近 24 小时 / 近 30 天」切换，默认 24 小时**
   - 排序用 `peers.rows[].r24 / r30`，金额用 `h24 / d30`；切换只重渲染，不重新请求
   - 榜单里 **Pons / StonkFun 两行用链上口径覆盖**（DefiLlama 会晚 1~2 天），其余协议走 DefiLlama
2. **三方对照表新增第一列「24 小时回购」**（Pons 链上现读 · STONK 链上快照 · pump.fun 用 DefiLlama 24h）
3. **两张销毁卡新增「近 24 小时回购」高亮小卡**：金额 + 笔数 + 来源标记（⚡链上现读 / 链上快照 / 数据源最近一日）
4. **前端新增 `loadChainBurn()`（真·实时）**
   - 打开页面 / 点「刷新数据」时，浏览器直连 `https://rpc.mainnet.chain.robinhood.com`：
     `eth_blockNumber` → 用 `bn-60000` 自校准出块速度（实测 ~0.102 秒/块）→ 反推 24 小时前的块高
     （最多修正 3 轮，容差 45 秒）→ `eth_getLogs` 筛 `Transfer(_, 0x…dEaD)` 求和
   - 顺带 `eth_call` 把「已销毁 / 总量 / 占比」也刷成当下值
   - **RPC 的 CORS 是 `*`，实测浏览器直连可用**；读不通就静默沿用快照，状态写在板块副标题里
   - 失败不影响其它数据：链上读数是 fire-and-forget，不打乱 DefiLlama / CoinGecko 的渲染节奏
5. **口径说明讲明白写在榜单下方**：哪些是实时、哪些会晚 1~2 天，不再让人猜（用户上一轮就是被这个搞糊涂的）

**数据来源分工（重要）**

| 数字 | 来源 | 时效 |
| --- | --- | --- |
| PONS 近 24h 回购 | Robinhood Chain RPC `eth_getLogs` | 实时（每次打开页面） |
| PONS 累计销毁 | 同上 `balanceOf(0x…dEaD)` | 实时 |
| STONK 近 24h 销毁 | `work/burn-history.json` 供应量差值（每小时最多一条快照） | 攒满 24h 后生效 |
| STONK 累计销毁 | Solana RPC `getTokenSupply` | 快照（每日心跳） |
| 全站回购榜 / 收入 / 价格 | DefiLlama / CoinGecko | 可能晚 1~2 天（不是我们能改的） |

**踩过的坑**

- ⚠️ 命名必须一致：写的是 `burn24hLive`，读的却是 `burn24live` —— 页面看着"同步成功"，标签却还是"链上快照"。
  改这块时**读写两端一起 grep**：`burn24hLive` / `burn24h` / `burn24hTxs` / `burn24hSrc`
- ⚠️ 手机端：新的 24h 小卡里塞了「金额 + 笔数 + 来源」，`.burn-kv span` 是 `nowrap`，会把卡片撑破 →

- ⚠️ 验证手机端别用 `--window-size=390`：新版无头 Chrome 的最小视口是 500px，量不出真机效果。
  用 **iframe 包一层**（`<iframe src=... style="width:390px">`）再截图，媒体查询才会按 390px 生效
- 线上验收命令：`curl -s "https://ponsfi.xyz/?v=30" | grep -o 'dashboard-version" content="[^"]*"'`
