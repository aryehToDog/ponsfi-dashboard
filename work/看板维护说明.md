## 云端数据管道（2026-10-07：抓取搬到 GitHub Actions，本机不再跑脚本）

> 一句话：**抓取在 GitHub 云上跑（海外节点，数据源全部直连），服务器每 5 分钟拉一份最新页面。**
> 作者电脑可以关机；腾讯云服务器（上海）也不需要翻墙。

### 为什么改

- 旧方案：Mac 上的 LaunchAgent → `work/hourly_check.py` → scp 上传。电脑一睡眠/关机，
  小时级数据就断档（曾断 14 小时）；桌面还得常年挂一个 Terminal 守护窗口。
- 服务器在上海：GeckoTerminal / CoinGecko / StonkFun 官网（Vercel）都被墙，
  常见中转到服务器也大多不通（实测 translate.goog / jina / codetabs 全挂，
  只有 allorigins 偶尔可用）——所以「服务器自己抓」这条路走不通。
- GitHub Actions 的 ubuntu runner 在海外，以上源**全部直连**；顺带天然满足
  「每次上线都同步到 GitHub」的长期要求。

### 新链路（三段）

```
GitHub Actions（.github/workflows/ponspulse.yml）
  · 每小时第 23 分钟（UTC）跑 hourly；每天 01:23 UTC（= 北京 09:23）跑 daily 全量
    （分钟选 :23 是有意的：GitHub 在整点前后负载最高，:00~:05 的定时最容易被延迟甚至跳过 ——
     2026-10-07 刚迁移当天 :05 连着 3 个整点都没触发，所以挪到低峰分钟）
  · 先 git fetch snapshots，把状态文件（sf-history / burn-history /
    dashboard-data / hourly / burns / burn_events）取回工作区
  · python3 work/ci_build.py --mode auto --push
      hourly：work/hourly.py → 合并进 dashboard-data.json → work/render_only.py
      daily ：work/build_monitor.py（DefiLlama 日线 / 收入榜 / 回购 / 小时级）
      auto  ：UTC 01 点走 daily；另外，最近一次全量超过 24 小时（定时被延迟 / 漏跑、
              或刚迁移还没跑过全量）时，下一个整点也自动补一轮 daily —— 日线数据不会
              一直卡在旧日期（2026-10-07 迁移当天就靠这条兜底补上了一轮）
  · 产物 + 状态打成孤儿提交，强推回 snapshots 分支（仓库永远只留最新一份）
        │
        ▼
GitHub 仓库 snapshots 分支（公开，可随时下载最新页面 / 数据快照）
        │
        ▼
腾讯云服务器（/home/ubuntu/ponspulse/，systemd 定时器每 5 分钟）
  pull_publish.sh：git fetch --depth=1 origin snapshots →
  原子替换 /var/www/pons-dashboard/index.html（先写 .new 再 mv，失败不动旧文件）
        │
        ▼
https://stonk1000x.top（Cloudflare 隧道 → nginx → 静态页；ponsfi.xyz 同步）
```

### 兜底触发（2026-10-07 加：GitHub 定时不触发时不让数据停更）

```
服务器 systemd 定时器 ponspulse-dispatch.timer（每 10 分钟）
  dispatch.sh：查 snapshots 快照多旧（api.github.com）
    · 快照 < 75 分钟 → 什么都不做（GitHub 定时一旦恢复，这里自动静默，不会重复跑）
    · 快照 ≥ 75 分钟 → POST workflow_dispatch（.gh-token，mode=auto）踢云端构建
    · 同一次触发后 25 分钟内不重复踢（防失败时连环踢）
        │
        ▼
  GitHub Actions 照常跑（抓取 + 渲染）→ 压回 snapshots → 服务器 5 分钟内发布上线
```

- 设计要点：**兜底而不抢班** —— 只按「快照新鲜度」决定要不要插手，和 GitHub 自带
  schedule、push 触发都不冲突（谁先跑都行，重复跑也只是多一份同样的快照）。
- token 权限：OAuth（GitHub CLI 应用）`repo + workflow`，只在服务器上；服务器被入侵时
  最坏影响也就是动这个仓库。失效判断：dispatch.log 里出现 `HTTP 401/403` → 跑
  `device-login.sh` 重新授权。
- 只读诊断：`curl -s -H "Authorization: Bearer $(cat /home/ubuntu/ponspulse/.gh-token)" \
  "https://api.github.com/repos/aryehToDog/ponsfi-dashboard/actions/runs?per_page=5"`。

## 主题系统（自动适配深色 / 浅色）

- 令牌定义在 `rebuild_template.py` 的 `DARK` / `LIGHT` 两段，浅色写了两遍（手动切换 + 跟随系统）

- 默认「跟随系统」：系统深色就深色，系统浅色就浅色
- 想让它**永远深色**：点按钮切到「深色」；或把 `rebuild_template.py` 里默认值 `||"auto"` 改成 `||"dark"`
- 所有颜色走 CSS 变量，图表颜色也用 `var(--pons)` / `var(--stonk)`，切主题不用重绘
- SVG 里颜色一律用 `style="stroke:var(--x)"`，**不能**用 `stroke="var(--x)"`（演示属性不支持 var()）

## 收入排行板块（v1.3 新增）

看板里「收入排行 · 在整个行业里的位置」这一块，数据来自 DefiLlama 全站收入榜
（`https://api.llama.fi/overview/fees?dataType=dailyRevenue`，约 2,455 个协议、原始 4.2MB）。

- **裁剪**：`work/leaderboard.py` 把 4.2MB 裁成 ~7KB，只留
  - 每个口径（24h / 7日 / 30日）的榜首 Top10
  - 两个目标协议的名次 + 上下各 4 名（已经在 Top10 里时改成「身后 8 名」）
- **快照**：结果写进 `work/dashboard-data.json` 的 `leaderboard` 字段，跟着面板一起发布
  - 只想更新排行、不重新抓收入：`python3 work/leaderboard.py` 再跑 `render_only.py`
  - ⚠️ Pons 的主协议 slug 是 **`pons-v2`**（`pons-v1` 已停用，24h 只剩几千美元）
- **页面刷新**：浏览器打开时若本地缓存超过 6 小时，会自己拉一次全站榜（gzip 后约 860KB，
  缓存在 localStorage 的 `pons-rank`）；也可以点板块里的「↻ 更新排行」强制拉
- **前端裁剪逻辑**：`template.base.html` 里的 `buildRankBoard()` 与 `leaderboard.py` 的
  `build_board()` 是同一套规则，改了一个要同步改另一个，否则快照和刷新结果会不一致

## 名次卡怎么读

| 元素 | 含义 |
|---|---|
| 大号 `#22` | 当前所选口径下的全站名次 |
| `前 1%` | 百分位（名次 ÷ 协议总数） |
| 对数刻度轴 | 左边是 #1（收入最高），右边是 #总数；标记越靠左越好，刻度是指数级的 |
| 三口径小卡 | 24 小时 / 7 日 / 30 日 各自的名次与收入额 |
| 环比那一行 | 30 日口径名次 → 现在名次（升 / 降多少位） |
| 紫色提示条 | 再涨多少「每日收入」就能超过上一名（同口径对比） |

## 浏览量统计（v1.4 新增）

页脚最下面一行「👁 总浏览 / 今日 / 今日访客」是**自己服务器上的计数器**，不接第三方统计。

```
访客浏览器 ── /api/hits ──▶ nginx 反代 ──▶ 127.0.0.1:8788 (pons-counter 服务)
                                              └─▶ /var/lib/pons-counter/counts.json
```

- 服务代码：`deploy/counter/counter.py`（纯 Python 标准库）+ `deploy/counter/pons-counter.service`（systemd）
- 服务器路径：`/opt/pons-counter/counter.py`，数据在 `/var/lib/pons-counter/counts.json`
- nginx：`/etc/nginx/conf.d/pons-dashboard.conf` 里的 `location = /api/hits`（备份 `.bak-pv`）
- 计数规则：每次打开页面 +1 次浏览；**同一天同一 IP 只算 1 个访客**；存的是加盐哈希，不存原始 IP；
  爬虫 / 探针（bot、spider、curl、wget、监控 UA）不计入；每天保留最近 400 天
- 本地 `file://` 打开**不计数**（只在 http/https 下才请求接口）
- 计数服务挂了页面不会报错，只是页脚不显示这一块

常用命令（在服务器上）：

```bash
systemctl status pons-counter          # 看服务状态
curl https://ponsfi.xyz/api/stats      # 只读看数字（不计数）
sudo systemctl restart pons-counter    # 重启
sudo rm /var/lib/pons-counter/counts.json && sudo systemctl restart pons-counter   # 清零重来
sudo journalctl -u pons-counter -n 30  # 看日志
```

改动计数服务后重新安装：把 `deploy/counter/` 三个文件传上去，`sudo bash install.sh`。

## 行情 BGM（v1.5 起多曲轮换 · v2.1 跌档三首 · v2.4 涨档两首）

- 涨档：`audio/up.mp3`《逍遥仙》→ `audio/up-bufan.mp3`《不凡》→ 来回轮换
- 跌档：`audio/down-meng.mp3`《梦的翅膀受了伤》→ `audio/down.mp3`《兄弟抱一下》→ 来回轮换
  （进跌档先放第一首；一首放完自动切下一首，靠 `ended` 事件驱动）
- 曲目表写在 `rebuild_template.py` 的 `BGM_TRACKS` 里，想加歌就往对应档位的数组里加一项：
  `{ src:'audio/xxx.mp3', name:'i18n 里的曲名 key' }`，并在 `template.base.html` 的 i18n 里补这个 key
- 轮换游标 `bgmRot`：每档记住"下一首该放第几首"；切档（涨↔跌）不会打断同档正在放的那首
- 只有一首的档位 `loop=true`（单曲循环）；两首及以上的档位 `loop=false`（放完换下一首）
- mp3 放服务器 `/var/www/pons-dashboard/audio/`，本机留一份在 `deploy/audio/`（zip 备份里不含 mp3）
- 文件缺失/加载失败 → 自动回落到内置原创占位旋律（Web Audio 合成），不会静音报错

**v2.0.1 补丁（2026-10-03，只上线了十几分钟就修掉的问题）**

症状：作者名片里共勉只占一半宽度、右边留一大片空白，长句被挤成两行；歌词块明明没显示却一直占着位置。

根因（**踩过的坑，别再踩**）：`QUOTE_JS` 里的状态量原来用 `let` 声明（`QBoxT / QRetryT / QN / QPend…`）。
- **函数声明会提升，`let` 不会** —— `qBoxShowSoon()` 在 `BGM_JS` 结尾的初始化（`lyricPaintIdle()`）时就被回调到了，而那时 `let QBoxT` 还在"暂时性死区"（TDZ），抛 `Cannot access 'QBoxT' before initialization`；
- 这个异常被初始化外面那层 `try{ lyricPaintIdle(); }catch(e){}` **静默吞掉**，于是 `lyricHide()` 后半段（620ms 后加 `hidden` 收起歌词块）根本没执行 → 歌词块永久占位。

修法：把这几个量改成 `var`（初始化为 undefined，不进 TDZ）。教训：
1. **跨模块（BGM_JS ↔ QUOTE_JS）被回调的函数，内部引用的状态量一律用 `var`**，别用 `let`；
2. 初始化包 `try/catch` 时至少 `console.warn` 一下，不然这类错误完全无声。

同时顺手做的观感调整：共勉正文 12.5px → 13px（一行能塞下最长那句）；点赞胶囊常驻**粉色心形 + 淡粉底**、`margin-left:auto` 靠右贴齐，和右边的「关注 / 打赏」连成一组，不再吊在句子后面。

#### 这一版加的四个派生值（都在 `stats()` 里）

#### 三处提示（中英都有）

        命令串里就带着这个路径，会自己匹配自己，永远以为还活着。）
     · plist `com.ponspulse.hourly`：`RunAtLoad=true` + `StartInterval=1800`，跑上面那个看门狗脚本。

## v3.12（2026-10-05）：内嵌 Inter · 三端同一个字形

**起因**：用户说「设计的越好看我都能接受」——同意把字体做到三端完全一致。

**为什么不是「随便换个字体」**：审计发现真正的差异在**字形跨平台不一致**——
同一个 `$1.28M`，Mac 渲染成 SF Pro、Windows 渲染成 Segoe UI、安卓渲染成 Roboto，
三种宽度三种粗细。要做「顶级」，先要**在任何设备上都长一样**。

**做法**
| 项 | 内容 |
|---|---|
| 字体 | Inter 可变字体（100~900 全字重），拉丁子集 |
| 来源 | `@fontsource-variable/inter` → `inter-latin-wght-normal.woff2` |
| 版权 | SIL Open Font License 1.1（免费商用、允许网页嵌入） |
| 原始体积 | 48,256 字节 → base64 后 64,344 字符 |
| 落盘位置 | 内嵌在 `work/template.html` 的 `<style>` 开头的 `@font-face`（data URI） |
| 源文件留档 | `work/fonts/inter-latin-wght-normal.woff2`（要重新生成时用它） |

**为什么内嵌而不是外链文件**：本站是「单文件应用」，而服务器 nginx 对整站
`Cache-Control: no-cache` —— 外链字体会变成**每次打开都重新下载**。内嵌后零额外请求、
零白屏、零跨域，也不需要在服务器上加目录、改 nginx。

**为什么中文不跟着换**：Inter 不含中日韩字形，浏览器会逐字回退到系统中文栈
（`苹方 → 鸿蒙 Sans → MiSans → 思源黑 → 雅黑 UI`）。这样做有两个好处：
① 不为了 Windows 好看而把 Mac 上公认最好的苹方换掉；② 页面 1021 个唯一汉字，
中文子集至少 250~500KB，而 HTML 每次访问都要重下，代价不划算。

**顺带修好的一件事**：`font-weight:800` 现在是真字重。此前 Windows 上 Segoe UI 最高
只到 Bold，`.hi`（关键数字）、`.rank-big`（排行大字）、`.tab.on`（选中标签页）想表达的
「更重一层」在 Windows 上是假的；Inter 可变字体 100~900 全支持。

**实测**
- `document.fonts` → `Inter | 100 900 | loaded`；
- 宽度对比法确认真的在用 Inter 渲染：同串数字 `Inter 233.06px` vs `system-ui 219.34px`；
- 1440 / 1024 / 768 / 390 × 暗 / 浅 共 8 组：页面溢出 0、窄容器裁切 0、最小字号 10.5px、
  控制台报错 0（只剩无头环境里被墙的行情接口）；
- 单文件 443KB → 509KB（+64KB）。

**回退**：删掉模板里那段 `@font-face`，并把 `--font-ui` 开头的 `"Inter",` 去掉。

## v3.13.2（2026-10-05）：图标动效层 · 有提示感，但不吵

**起因**：用户看完 v3.13.1 反馈「如果图标再加上一些动画效果就更好了，有一种提示的感觉」。

**设计原则**：动效分三类，全部有含义，不为动而动。

| 类 | 动效 | 含义 |
|---|---|---|
| ① 入场提示 | 板块滚进视野时，图标胶囊弹一下（`icPop .68s`）+ 放一圈淡光，一次性 | 「这里是一个新板块」 |
| ② 状态提示 | 链上现读的实心闪电常驻呼吸（`icBreath 2.8s`）；告警条 / 风险标每轮渲染轻跳一下（`icAlert`） | 呼吸 = 数据是实时的；轻跳 = 有事要处理 |
| ③ 手感提示 | 悬停微反应：主题按钮翻转 -22°、刷新按钮倒转 -52°、打赏咖啡上跳、浏览量眼睛眨一下、榜单名次放大 | 「这里可点」 |

**图标胶囊**：板块图标从 18px 裸图标升级为「20px 图标 + 4px 内边距 = 28px 胶囊」，
底色是 `{PONS 紫 → STONK 绿}` 各 16% 的极淡渐变 + 1px 同色描边（`color-mix`，深浅主题自动适配）。
**原 `.sec-title::before` 的 3px 渐变竖条已 `display:none` 退役** —— 两条左侧标记一起太满，
胶囊本身就是左侧标记。

**入场怎么触发（踩坑记录，重要）**：
第一版用 `IntersectionObserver`。回归测试发现「网页一步跳到底部」或「点锚点直接跳转」时，
中间那些从没进入过视野的板块**不会产生任何回调**，图标会永远停在 `opacity:0`。
**已改为 rAF 节流的滚动扫描**（`icRevealInit()`，在 `qInit()` 后调用）：
判定条件 `rect.top < vh * 0.94 || rect.bottom < 0`（后者专治「已经被滚到上方」的情况），
全部点亮后自动摘掉监听。三种极端场景（一步到底 / 锚点跳转 / 反复上下）实测 8/8 全亮。

**无障碍**：`prefers-reduced-motion: reduce` 下所有 animation 置 `none`、transform 置 `none`、
图标 `opacity` 兜底为 1 —— 动效党有动效，晕动症用户看到的是静态但完整的界面。
`<html class="ic-motion">` 由 `<head>` 末尾一段内联脚本在首帧前打上，避免入场动画闪一下；
无 JS 时图标照常显示（不会因为缺类名而消失）。

**实测（16 组回归）**：1440 / 1024 / 768 / 390 × 暗 / 浅 × 常规 / 减弱动效 ——
`opacity=1×8`、`animation=icPop×8`（减弱动效下 `none×8`）、溢出 0、容器裁切 0、报错 0、
图标引用缺失 0、最小字号 10.5px。滚动入场实测（1440）：首屏 1/8 → 滚到底 8/8；
390 手机首屏 0/8 → 滚到底 8/8，符合「滚到哪亮到哪」。

### 版本发布（2026-10-04 起）：每次上线自动打标签

- 每次「源文件上线」（模板 / 脚本有改动）后，`work/git_sync.py` 会自动：
  1. 提交并推送 main；
  2. 打一个**带更新说明的版本标签**并推送 —— 去 GitHub 仓库的 Tags 页就能逐版回看。
- 标签名怎么定：
  - 这一版改了页脚版本号（`work/render_only.py` 里的 `VER`，如 `v3.5`）→ 标签就叫 `v3.5`；
  - 否则在最近版本标签的补丁位 +1（`v3.5.1`、`v3.5.2` …）。
- 标签说明 = 自上个版本以来的提交清单 + 改动文件统计（脚本自动生成）。
- 只是「数据刷新、源文件没动」的那一小时不会打标签（避免一天 24 个版本）；
  整站快照照旧每小时进 `snapshots` 分支。
- 手动发一版：把 `render_only.py` 的 `VER` 改成新版本号 → 正常上线一次即可。
